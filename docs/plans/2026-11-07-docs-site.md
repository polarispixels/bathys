# Docs Site Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A public `/docs` site that renders the repository's markdown, with a front page whose status block builds itself from `package.json`, `CHANGELOG.md`, and `docs/roadmap.md`, plus `.md` endpoints and `/llms.txt` for agents.

**Architecture:** Plain PHP classes in `app/Docs/` (a catalog built by scanning the repository, a CommonMark renderer with a link rewriter, two small parsers for the status block) behind one controller and three Blade views. No database, no session, no Inertia. Everything takes a root path, so unit tests run against a fixture repository under `tests/Fixtures/`.

**Tech Stack:** Laravel 13, PHP 8.4, `league/commonmark` 2.10 (installed), `@tailwindcss/typography` (new dev dependency), Blade, Pest.

**Spec:** `docs/designs/2026-11-07-docs-site-design.md` and `docs/adr/0011-docs-site-rendered-from-the-repository.md`.

## Global Constraints

- Nothing in `core/` changes. All new PHP lives in `app/Docs/` and `app/Http/Controllers/DocsController.php`; it may use `Illuminate\` freely.
- `declare(strict_types=1);` in every new PHP file; return types on every method; PHPDoc array shapes for arrays. Larastan level 7 must pass.
- No em dashes in copy, docs, or commit messages. Plain words.
- Tests make no network calls. Unit tests read only `tests/Fixtures/docs-site/`; feature tests read the real repository through `base_path()`.
- Slugs are looked up in the catalog; the request path never becomes a filesystem path.
- Commit messages: Conventional Commits, scope `web` (`feat(web): ...`, `test(web): ...`), body ending with the attribution lines the dispatch brief gives you. One commit per task.
- Run `vendor/bin/pint --dirty --format agent` before each commit, then `composer test` on its own (never piped) and gate the commit on its exit code.
- Every task adds its line under `## [Unreleased]` in `CHANGELOG.md` (`### Added`).

## Review Focus

1. A document with a relative link to a markdown file that is not in the catalog (`docs/plans/` before any plan existed, or a deleted ADR) must become a GitHub link, never a broken `/docs/...` link. Test in Task 2.
2. A slug that differs only in case from a real one (`/docs/SPEC`) must be 404, not a Windows-style match. Test in Task 3.
3. A roadmap row whose status starts with a word other than `done`, `next`, or `planned` (for example `designed (...)`) must still render, with the text as written and no badge class. Test in Task 4.
4. The latest changelog entry's paragraph may be missing (a release with only `### Added` lists); the front page must still render with the version line alone. Test in Task 4.
5. `/llms.txt` must use the public base URL, not `http://localhost`, so an agent that fetches it from production gets fetchable links. Test in Task 5 (asserts links start with `config('app.url')`).

### Task 2: The renderer and link rewriting

**Files:**
- Create: `app/Docs/MarkdownRenderer.php`, `app/Docs/LinkRewriter.php`, `config/docs.php`
- Modify: `composer.json` (`composer require league/commonmark:^2.10 --no-interaction`; it is already installed through Laravel, this only declares it), `.env.example` (`DOCS_REPOSITORY_URL=` with a one-line comment)
- Test: `tests/Unit/Docs/MarkdownRendererTest.php`

**Interfaces:**
- Consumes: `DocsCatalog`, `DocPage` (Task 1).
- Produces: `final class MarkdownRenderer { public function __construct(private DocsCatalog $catalog, private ?string $repositoryUrl, private string $docsBaseUrl = '/docs'); public function render(DocPage $page): string /* HTML */; public function renderInline(string $markdown): string /* HTML without the wrapping <p>, for table cells */ }`
- Produces: `config('docs.repository_url')`, read from `env('DOCS_REPOSITORY_URL')` with no default (null until Ryan decides whether the repository goes public). GitHub file links are `{repository_url}/blob/main/{path}`.
- `LinkRewriter` is a listener for `League\CommonMark\Event\DocumentParsedEvent`; it walks `Link` nodes and rewrites relative URLs (no scheme, not starting with `#` or `/`): resolve against the page's folder relative to the repo root (normalize `..`), then `catalog->relativePathToSlug()`; a hit becomes `{docsBaseUrl}/{slug}` (`{docsBaseUrl}` alone for the front page) with the fragment kept; a miss becomes `{repositoryUrl}/blob/main/{normalized path}` when `$repositoryUrl` is set, and otherwise the link node is replaced by its own children (plain text, no `<a>`).
- Environment: `CommonMarkCoreExtension`, `GithubFlavoredMarkdownExtension`, `HeadingPermalinkExtension` with `['insert' => 'none', 'apply_id_to_heading' => true, 'id_prefix' => '', 'fragment_prefix' => '']`, `html_input => 'strip'`, `allow_unsafe_links => false`.

### Task 4: The self-updating front page

**Files:**
- Create: `app/Docs/ReleaseNotes.php`, `app/Docs/Release.php`, `app/Docs/RoadmapBoard.php`, `app/Docs/RoadmapPhase.php`, `app/Docs/RoadmapRow.php`
- Modify: `app/Http/Controllers/DocsController.php` (`index`), `resources/views/docs/index.blade.php`, `docs/index.md` (final wording)
- Test: `tests/Unit/Docs/ReleaseNotesTest.php`, `tests/Unit/Docs/RoadmapBoardTest.php`, `tests/Feature/DocsSiteTest.php` (add cases)

**Interfaces:**
- Produces: `final class ReleaseNotes { public static function latest(string $changelog, string $version): ?Release }` and `final readonly class Release { public function __construct(public string $version, public string $date /* YYYY-MM-DD */, public string $summary /* markdown paragraph, may be '' */) }`. It finds the line `## [{version}] - YYYY-MM-DD` and takes the text between it and the next line starting with `#`; if the heading is missing, return null.
- Produces: `final class RoadmapBoard { public static function fromMarkdown(string $roadmap): array /* list<RoadmapPhase> */ }`, `final readonly class RoadmapPhase { public string $title; /** @var list<RoadmapRow> */ public array $rows }`, `final readonly class RoadmapRow { public string $step /* '' when the table has no Step column or the cell is empty */; public string $item /* markdown */; public string $status /* as written */; public ?string $badge /* 'done', 'next', or 'planned' when the status starts with that word, else null */ }`. A phase is a `## ` heading; its rows are every `|`-delimited line after it (before the next `## `), skipping the header row and the `|---|` separator. Tables with columns `Item | Status` give `step = ''`; tables with `Step | Item | Status` map in order. Phases with no table rows are left out.
- The front page view shows, after the rendered `docs/index.md`: a "Where things stand" section with "Version X.Y.Z, released Month D, YYYY" linking to `/docs/changelog`, the release summary rendered with `renderInline`, then one table per phase (step, item via `renderInline`, status with a `<span class="badge badge-{badge}">` when badge is set, plain text otherwise). When `ReleaseNotes::latest()` is null or the board is empty, that piece shows "See the [roadmap](/docs/roadmap)." instead.
